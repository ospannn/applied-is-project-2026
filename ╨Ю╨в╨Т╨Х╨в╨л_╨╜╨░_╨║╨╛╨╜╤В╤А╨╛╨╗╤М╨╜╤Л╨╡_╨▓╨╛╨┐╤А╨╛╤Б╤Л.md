# Ответы на контрольные вопросы (ЛР №1 и №2)

## ЛР №1

**1. Зачем нужен venv?**
Виртуальное окружение изолирует библиотеки проекта от системного Python и других проектов. Без него все пакеты ставятся глобально: разные проекты требуют разные версии одной библиотеки и конфликтуют, засоряется системный Python, сложно воспроизвести окружение на другом компьютере.

**2. Для чего .gitignore и почему в нём venv и файлы с паролями?**
Файл говорит Git, какие файлы не отслеживать. venv весит сотни мегабайт, создаётся командой и зависит от ОС, поэтому в репозитории он не нужен. Файлы конфигурации с паролями (.env) нельзя публиковать: в публичном репозитории их увидят все, а удалить из истории коммитов сложно. Ключи придётся считать скомпрометированными.

**3. Роль Cursor / ИИ-плагинов и риски слепого копирования.**
ИИ-среда ускоряет рутину: генерирует каркас, шаблонный код, объясняет ошибки. Риски: код может содержать ошибки или устаревший синтаксис, выдуманные библиотеки и функции, уязвимости (например, небезопасная работа с паролями), не соответствовать задаче. Разработчик отвечает за код и должен понимать каждую строку, проверять и тестировать результат.

**4. Что такое ветвление (git branch) и почему нельзя писать прямо в main?**
Ветка — независимая линия разработки. В ней делают новую функцию или исправление, не ломая рабочий код. main содержит стабильную версию, которую используют или разворачивают на сервере. Новый код попадает в неё через merge/pull request после проверки (code review, тесты). Так ошибка не попадёт в рабочую версию, а работа нескольких людей не конфликтует.

**5. Разница между git commit и git push.**
`git commit` сохраняет снимок изменений в **локальный** репозиторий (папка .git на вашем компьютере). `git push` отправляет локальные коммиты в **удалённый** репозиторий (GitHub). Пока нет push, на GitHub изменений нет.

## ЛР №2

**1. Что такое ORM и какую проблему решает?**
Object-Relational Mapping — отображение таблиц БД на классы Python, а строк на объекты. Разработчик работает с объектами и методами, а не пишет SQL вручную. Это сокращает код, снижает число ошибок и риск SQL-инъекций, упрощает смену СУБД (SQLite → PostgreSQL).

**2. category_id и category — в чём разница?**
`category_id` — реальный столбец таблицы (внешний ключ на `category.id`), в SQL это колонка с ограничением FOREIGN KEY и числовым значением. `category` — Relationship, объектная связь на уровне Python: через неё можно обратиться к связанному объекту (`item.category.name`). Отдельного столбца в БД для неё нет, ORM сама делает JOIN или дополнительный запрос.

**3. Зачем нужен seeding?**
Seed-данные нужны, чтобы проверять работу системы: тестировать выборки, связи, API и интерфейс. На пустой базе нечего показывать и сложно заметить ошибки. Скрипт делает наполнение воспроизводимым: любой разработчик получает одинаковую тестовую базу одной командой.

**4. Роль echo=True в create_engine.**
Движок выводит в консоль все выполняемые SQL-запросы (CREATE TABLE, INSERT, SELECT). Это помогает отлаживать: видно, какой SQL генерирует ORM, сколько запросов выполняется и где ошибка.

**5. Почему database.db в .gitignore, а models.py в репозитории?**
models.py — исходный код, из него любой воссоздаст структуру БД. database.db — генерируемые данные: он бинарный, у каждого разработчика свой, вызывает конфликты при слиянии и может содержать реальные или персональные данные. Структуру восстанавливают через init_db(), данные — через seed.py.

## Что нужно сделать вручную (то, что нельзя сделать за вас)
1. Создать публичный репозиторий `applied-is-project-2026` на GitHub (с README и .gitignore для Python).
2. `git clone <ссылка>`, скопировать в папку файлы проекта, затем:
   ```bash
   git add .
   git commit -m "feat: initial project structure with AI assist"
   git push origin main
   git add app/ seed.py
   git commit -m "feat: add SQLModel ORM models and database seed script"
   git push origin main
   ```
3. Установить Cursor или VS Code, создать venv, выполнить `pip install -r requirements.txt` и `python seed.py`.
4. Сделать скриншоты: репозиторий на GitHub, терминал с CREATE TABLE/INSERT, ER-диаграмма.
5. Просмотреть код и быть готовым объяснить назначение каждого файла (это 3 балла из 10 в каждой лабе).
